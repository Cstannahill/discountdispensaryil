# Shared notes across fix sessions

- [branch-proof] Worktree setup: `browser_worker.cjs` requires `../frontend/node_modules/playwright`, so a fresh worktree's browser fallback dies with "[Errno 32] Broken pipe" until you link it: `New-Item -ItemType Junction -Path <worktree>\frontend\node_modules -Target S:\Code\Other\terpscout_fullstack\frontend\node_modules`. Run scripts from the main checkout (`cd S:\Code\Other\terpscout_fullstack; .venv\Scripts\python.exe .worktrees\<wt>\scripts\triage_region.py ...`): the script imports the worktree's backend and reads the main `terpscout.db` / `data/evidence`.
- [branch-proof] Sweed multi-store sites (Mystic Greenz, Altius, Revolution, Ivy Hall) open on a default branch. The store home page's SSR cache carries `/Store/GetStoreShortInfoList` (every branch: name, contacts.address, url); category/menu pages often don't, so read `storeInfo.url` (the default store's home). `storeInfo.location.coords` is the branch's own pin (good branch proof when the registry street number is mistyped).
- [followups] Some chains run a platform client-side and fetch ONE whole-branch catalog JSON instead of paging (Zen Leaf: `data.zenleafdispensaries.com/catalog/<sweedId>/<recreational|medical>`, ~1 MB, 850-1350 variants). Look for it in a probe's `network_json` (largest JSON response) before writing a paged/browser traversal. Plain HTTP GET works; no total, so two agreeing reads = grade B.
- [followups] Sweed store lists also appear in Next Flight data as `sweedStores` (same shape as `/Store/GetStoreShortInfoList`: id, name, contacts.address, location.coords, saleTypes, url). `backend/providers/verano.py:store_list` reads it; `locators._known_menu_candidates` now uses it, and a store-list pin within 0.35 mi of the registry point counts as a match (`locators._pinned`).
- [followups] `addresses_match` now maps "Illinois Route 59" to "IL Rte 59" and drops "Spc"/"Space" unit suffixes.
- [branch-proof] Name/town spellings now match in `inspect_page` / `branch_slug_conflict` (b45091c): run-together or split brands ("Star Buds" = "Starbuds", words of 6+ letters), trailing "Village" dropped ("Elk Grove" = "Elk Grove Village", slug "elkgrove"), Mt/St/Ft = Mount/Saint/Fort. Use `site_discovery.locality_in` / `locality_words` instead of raw city word sets.
- [branch-proof] Jane white-label WordPress sites (Heady "JaneBoost", e.g. nueracannabis.com) carry every store in script as `hjb_store_url_ids` {url `/shop/store/<id>`, title "Town (REC)"}; `site_discovery.janeboost_store_links` picks the requested town's pages and the Jane reader proves them by `_geoloc`.
- [branch-proof] Triage at `--pages 1` always shows Blaze as `items=0` ("configured page limit reached"): the Blaze reader keeps items only after a full pass. Use `--pages 15` for Blaze stores (API only, ~1 s).

- [curaleaf-gate] Age gates that keep the confirm button disabled until a terms checkbox is ticked: tick terms first, then click "I'm over 21" (browser_worker.cjs confirmAgeOnce). Check the button is enabled before clicking.
- [curaleaf-gate] A gated home page can hide branches: the retailer's robots.txt `Sitemap:` entries (e.g. dispensaries-sitemap.xml) list each branch's own URL (`/shop/<state>/<branch-slug>`). Match on state segment plus city or street in the slug (locators._sitemap_branches). Sweed branch pages behind the sitemap can still carry another street (Morris, New Lenox): address proof is still required.
