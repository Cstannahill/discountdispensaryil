## Root causes, most widespread first

1. **Website discovery is dead (about 16 of the 20 no-endpoint stores).** `html.duckduckgo.com` returns HTTP 202 with a bot challenge; `www.bing.com/search` returns 200 with unrelated Microsoft pages for the quoted-address query (stored evidence, curl and headless Chrome all agree). 62 stores registry-wide have NO_LEAD as their latest resolution. Every NO_LEAD store here has a public site and a mappable menu. Brand-level locators beat search: Ascend `letsascend.com/wp-json/ascend-store-mapper/v1/locations` (all IL stores with `shop_url` + `dutchie_cname`), Ivy Hall `/locations/` `var locations_data` JSON, Verilife `/locations`, Curaleaf `dispensaries-sitemap.xml`, Dutchess/Maribis/Bud & Ritas `/stores/` pages. Fix: a real search source (the OpenRouter web plugin the verifier already uses) plus one connector per chain; treat a results page naming nothing about the store as a search failure.
2. **Dutchie is the biggest platform gap (10 stores).** High Profile Springfield, Dutchess x3, Maribis Westchester, Stashouse Moline are Dutchie Ecommerce Pro/Plus on the retailer's own domain (`/stores/<slug>`, same-origin `GET /api-N/graphql`, persisted query `FilteredProducts`, one `dispensaryId` in the SSR HTML). The four Ascend stores moved from Dispense to Dutchie (`letsascend.com/stores/<cName>`, `/api-4/graphql`). `dutchie_page_endpoints()` already turns such pages into `dutchie.com/embedded-menu/<id>` (helper ran it on the fetched pages); the failure is upstream (discovery lands on a sibling branch or chooser page) and in paging: default `sortBy=popular` has ties (Markham reached 511 of 514; `sortBy=name`, `isDefaultSort=false` gave 514), and `removeProductsBelowOptionThresholds=true` drops products (Oak Park 792 vs 799). perPage cap is 100. Detection must key on `assets2.dutchie.com` + `dispensaryId`, not the dutchie.com hostname.
3. **Working menus are stale because nothing refreshes them (10 stores).** Jane: Consume Oakbrook Terrace, Consume Chicago, Beyond/Hello Bloomington, Beyond/Hello Normal, High Haven, EarthMed (med), Nuera (med); Sweed: Aroma Hill Kankakee, Tree Haus Morris; Ivy Hall Bolingbrook is suspicious (see 6). Helper finding: the scheduled `menu-sync` enqueues only `active_region_id` `ad41b2e9` (a 50 mi GPS region), the 06:00 and 12:00 CDT slots never ran (server down), and the Minonk 100 mi region is only touched by manual jobs. With a correctly hydrated endpoint these all fetch complete (see 8).
4. **Stale or wrong endpoints attached to a store.** Ascend Springfield's accepted "grade A" Dispense menu is a frozen snapshot (newest product modified 2025-11-11, medical-only) and Chicago Ridge's endpoint is a 7,540-URL `sitemap.xml`; Zen Leaf Aurora carries about 19 generic rows from other branches/states; Consume x2 carry Antioch/Marion Jane endpoints (rejected by distance, so no wrong offers); Bloom Wellness Normal carries Northbrook rows and is served by generic grade B (hidden from `/deals`); Cannabist Villa Park has `checkout`/`featured` rows; Stashouse adopted a chooser page; Sunnyside's root URL lets the SPA pick the store by IP (it picked Champaign). Fixes: `branch_slug_conflict` guard for native providers, supersede the leaks, reject XML as a menu, a source-age guard (`product.modified`) for Dispense.
5. **Platform provider gaps.** Cresco/Sunnyside and white-labels (Sunnyside Chi-River North store 493, Shangri-La store 970): `adapters.py:141` only recognises Cresco on `cloud9dispensaries.shop`; detect by `api.crescolabs.com` calls and add a native provider (a storefront key is needed; not recorded anywhere). Treez (Stash Richton Park): traversal budget exceeded; helper's replay of the allowlisted gapcommerce POST uncollapsed, size 100, sort `[{_id:'asc'}]` reached 1426 = `hits.total` in 15 requests. Jane: script-loader embeds (The Dispensary Fulton rec 4056, Happy Cannabis Loves Park rec 3769, default store there is Rockford 1410) hide the numeric id until render (`#jane-store-id[data-store-id]`, `api.iheartjane.com/v1/stores/<id>`); EarthMed's unquoted `storeId: N` is not matched (adapters.py ~L138); Nuera's rec twin (1519) is missed because `links[:10]` is eaten by `?filters[...]` links; rec twins EarthMed 2758 and Nuera 1519 are missing from the DB. Verano (Zen Leaf, Sweed ids 539/537): HEAD's `providers/verano.py` should work but needs a re-run; its medical and recreational feeds are byte-identical, so license labelling is not independent evidence.
6. **Sweed `/menu/discounts` canonicalisation (Ivy Hall Bolingbrook, medium confidence).** Saved endpoints are the discounts view; snapshots went complete 1225, then suspicious 368, then 357; `GetProductList` on that route reports total 323. Canonicalise Sweed to `/menu`.
7. **Identity/address mismatches.** Ascend Midway (5648 vs 5650 S Archer, about 1.4 mi), Dutchess Oak Park (1132 vs 1142 Lake), Aroma Hill Peoria (1210 vs 1204 W Glen, 0.027 mi apart), Rise/Verilife/Bloom (Rise JSON-LD writes `#103 Quincy Ave 1700`, so `inspect_page` reports a conflict), Beyond/Hello Bloomington (registry 118 Keaton Place = retailer 1515 N Veterans Pkwy), Normal's Jane point 3.25 mi from the registry point. Need named exceptions or `retailer_location` coordinates treated like Jane's `platform_location`.
8. **Tooling defect: `scripts/sample_stores.py` false negatives.** It passes the raw `live_endpoints` row; `Store.endpoint()` merges `resolution_json`, which carries `identity_confidence` that `providers/jane.py` needs for platform points 0.35-5 mi away. Correct Jane endpoints therefore show 0 items. Merged, they return complete: Consume Oakbrook Terrace 858, Consume Chicago rec 901 / med 900, Beyond/Hello Normal rec 1008 / med 1014, EarthMed med 1329, Nuera med 1347. It also samples the most recently attempted endpoint, often another branch's.
9. **Other.** Curaleaf Lincoln Park: every route 307s to `/age-gate`; the button stays disabled until a state `<select>` and two checkboxes (one is "I agree to the Terms of Use") are set; `browser_worker.cjs` has no `<select>` handling. The helper stopped before the Terms box: accepting terms needs your decision. Rise's IL directory (`risecannabis.com/api/opensearch/dispensaries/nearest`) works from a browser page context but returns Cloudflare 403 to plain clients, so it is a block to report, not evade. `thehappycannaco.com` returns 403 to headless Chrome only. Grasshopper Logan Square is temporarily closed (fire).

## Suggested fix order
1. Replace the dead fallback search and add chain connectors (Ascend, Ivy Hall, Dutchess, Maribis, Bud & Ritas, Altius, Bisa Lina, Zen Leaf/Verilife/Rise, Curaleaf list): unlocks about 16 stores with natively supported platforms.
2. Dutchie same-origin storefront detection plus stable paging (10 stores).
3. Scheduler: include the Minonk region (or every region with endpoints) and add a source-age guard for frozen menus.
4. Endpoint hygiene: native-provider branch-slug guard, supersede leaked endpoints, reject XML, canonicalise Sweed to `/menu`.
5. Jane resolver fixes (script-embed store id, unquoted `storeId`, link cap before filter, rec twins), then a native Cresco provider and the Treez uncollapsed replay.
6. Fix the sampler (merge `resolution_json`, accept an endpoint id) before using it for more acceptance claims.
